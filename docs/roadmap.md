# v2.2 路线图与验收清单

更新日期：2026-10-21。当前收尾版本：v2.1.0；下一版本：v2.2.0。

本路线图承接 v2.1 的全部未完成、未验证事项。历史原始清单见 [v2.1 roadmap 归档](archive/v2.1.0-roadmap.md)（恢复自 bd2e4ac，保留原文及当时状态）；当前实现以[架构说明](architecture.md)为准。P0 必须优先于体验扩展，未完成的功能不得作为 v2.1 已交付能力。

- [ ] 核对全部图片和正文，明确发布素材范围，保留原始阅读材料与运行数据在本地。

## 2. P0：完整面试流程与 Agent 分工

- [ ] 确定开场、提问、澄清、追问、结束、评估的状态机；为每阶段定义输入、结构化输出、允许迁移、终止条件与失败处理。
- [ ] 新增开始面试接口与 UI，由面试官先开场，避免要求面试者先发消息。
- [ ] 设计辅助总结 Agent（旧清单名 AssiantAgent）：触发时机、摘要粒度、证据来源、状态更新及追问输入。
- [ ] 明确 AssessAgent 与 EvaluateAgent 的职责，确定是否需要拆分；交付评分标准、回答证据和最终反馈报告，旧版评分不算已迁移。
- [ ] 以正常、信息不足、重复提交、模型失败样例验证编排；先稳定状态机与评价标准，再抽取可复用 Skill。MCP 与 Harness 仅在出现外部服务或受控执行需求后另行评估。

## 3. P0：简历上传、解析与面试上下文

- [ ] 实现前端约定的会话级 PDF 上传接口，对齐响应字段与错误码；当前只有前端，后端旧入口返回 501。
- [ ] 校验大小、类型、存储路径与会话归属，明确移除关联和删除文件的区别。
- [ ] 解析简历文本并接入 Agent 上下文；文件路径不等于已读取简历。
- [ ] 验收正常、空文件、损坏 PDF、扫描件、超限、上传重试及解析失败，确保不会伪报成功。

## 4. P1：中断、恢复与持久化

- [ ] 分别定义取消模型调用、停止发送响应和结束整场面试；验证各时机的消息、轮次、取消传播及可继续性。
- [ ] 完善断流后的同步与用户提示，避免未确认回复被重复提交。
- [ ] 如需跨重启恢复或多 worker，实施持久化检查点、数据迁移与恢复测试；当前仅进程内恢复。
- [ ] 如引入账户体系，实现会话归属与访问控制；UUID 不能作为授权。

## 5. P1：预设契约与 OpenAPI SDK

- [ ] 复核预设保存、列举、加载、删除以及写入会话的契约；内部路由拆分已实现，删除已实现，不沿用旧清单的空实现描述。
- [ ] 决定是否将预设 URL 迁移至 /presets；若迁移，提供旧新映射与兼容策略，同步前端及测试。
- [ ] 明确配置更新后自动保存预设是否保留，以及同名覆盖、部分成功和后续数据库迁移策略。
- [ ] 稳定 OpenAPI tags、请求/响应模型和 operationId；以 Hey API 为候选验证 TypeScript SDK，固定规范输入和生成目录。
- [ ] 在开发与 CI 中校验规范、SDK、类型和构建同步；以接口字段变更验证旧调用能被检查发现，生成目录不得手工维护。

- [ ] 检查序厅、准备、面试室、回顾、人物列表/正文及弹窗的加载、错误、聚焦和禁用状态。
