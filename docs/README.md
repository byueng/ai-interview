## 维护规则

1. **当前实现只在架构说明中集中维护。** 发布说明仅概括本版本变化，通过链接引用技术细节。
2. **活动待办只在路线图中维护。** 完成后补充日期和验证依据；随版本发布记录成果，不再并行维护多份待办。
3. **发布记录保留时间语境。** 发布时的限制和计划不随日常开发反复改写；发现事实错误时，应注明更正原因。
4. **历史记录不冒充当前结论。** 归档文件保留原始日期、测试范围和决策背景，失效描述通过归档提示说明。
5. **区分实现与验证。** 代码存在、模拟测试通过、真实模型联调和完整业务验收分别记录，不能相互替代。
6. **控制文档数量。** 不再单设 `development`；只有需要长期保留的设计取舍或验证过程才新增归档记录。

发布文件统一使用 `v主版本.次版本.修订版本.md` 命名。本次将原 `v.2.0.md` 统一为 `v2.0.0.md`，仅调整文档命名与展示，不修改程序包版本。
