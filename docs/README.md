## 维护规则

1. **发布记录保留时间语境。** 发布时的限制和计划不随日常开发反复改写；发现事实错误时，应注明更正原因。
2. **区分实现与验证。** 代码存在、模拟测试通过、真实模型联调和完整业务验收分别记录，不能相互替代。
3. **公共文档只引用已发布文件。** 当前实现、活动计划和开发归档在本地维护，不作为公开链接。

发布文件统一使用 `v主版本.次版本.修订版本.md` 命名。本次将原 `v.2.0.md` 统一为 `v2.0.0.md`，仅调整文档命名与展示，不修改程序包版本。
