发布日期：2026-10-13

## 版本概述

本版本以面试流程编排和后端结构重构为重点，将 Agent 执行流程迁移至 LangGraph，引入基于会话标识的状态管理、异步模型调用和 SSE 事件响应。前端页面延续旧版整体风格。

本版本记录的是当前重构阶段的成果，不意味着 v1.x 的题库、评分、SQLite 等能力已经全部迁移。

## 本版本变更

- **流程编排**：使用 `StateGraph` 和 `TaskState` 管理单轮面试，当前链路为 `START → InterviewAgent → END`；通过 `add_messages` 合并消息，成功回复后更新轮次。
- **后端结构**：继续使用 FastAPI，以 `APIRouter` 组织接口，拆分应用组装、路由、业务服务与文件写入职责，并使用 Pydantic 定义请求模型。
- **基础接口**：实现会话创建、面试者与面试官配置写入，以及面试对话入口。
- **异步响应**：通过异步模型与 Graph 调用处理对话，使用 SSE `message`、`error` 和 `done` 事件传递节点更新、处理失败和正常结束信号。
- **短期记忆**：将会话 UUID 映射到 `configurable.thread_id`，使用 `InMemorySaver` 管理进程内会话状态。
- **文件导出**：新增执行前状态快照与面试预设保存；写入前转换为 JSON 兼容类型，文件写入在线程中执行。

## 发布时的能力边界

- 当前 SSE 输出节点更新，不是逐 token 输出；每次 Graph 执行只生成一次面试官回复。
- 会话状态保存在内存中，重启或开发热重载后不会自动恢复；JSON 导出尚未接入检查点恢复。
- 快照反映本轮消息提交前的状态；预设仅保存面试者和面试官配置，同名岗位会覆盖旧文件，加载与回填未实现。
- 仅接入 `InterviewAgent`；辅助、评估 Agent 和简历上传仍未形成完整能力。
- 会话失效、配置缺失、文件写入失败及并发请求等场景仍需完善；预设保存异常尚未纳入路由现有的统一 SSE 错误处理。
