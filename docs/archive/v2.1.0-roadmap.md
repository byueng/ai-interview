# 路线图与验收清单

更新日期：2026-10-20

本文件是活动待办的统一入口。已存在的代码不自动等于已验收；各项以注明日期、方式和证据的完成记录为准，未验证项保持未勾选。

## 4. 面试流程与 Agent 能力扩展

状态：设计中，尚未接入执行图。

### 4.1 技术定位与实施顺序

当前目标不是堆叠 Prompt、MCP、Agent、Skill 与 Harness，而是让每一层解决明确的问题。已存在的单轮 `InterviewAgent`、`TaskState` 与 LangGraph 执行图是后续扩展的基础，但不代表下列设计已完成。

- [ ] 以“状态机约束下的单 Agent”作为当前主线：由确定性流程控制开场、提问、澄清、追问、结束和评估阶段；模型只承担回答理解、内容生成及受限的下一步建议，不能自由决定整个业务流程。
- [ ] 为每个面试阶段定义输入、允许状态迁移、输出结构、终止条件和失败处理；用正常、信息不足、重复提交及模型失败样例验证迁移结果。
- [ ] 保留 Prompt 作为阶段行为与上下文的配置方式，避免将 Prompt 模板本身表述为独立的 Agent 能力。
- [ ] 在单 Agent 流程和评价标准稳定后，再将岗位题纲、追问策略、评分 rubric 等可复用领域能力抽成 Skill；明确每个 Skill 的输入、输出、版本和测试样例。
- [ ] 暂不引入 MCP：只有需要以标准协议访问外部招聘系统、日历、知识库或其他独立服务时，才评估工具发现、鉴权、最小权限和调用审计。
- [ ] 暂不引入 Harness：当前浏览器面试应用没有执行命令、操作文件或运行长任务的需求；若后续引入此类受控执行环境，再单独定义沙箱、资源回收和安全边界。

验收依据：给出状态迁移记录与结构化输出，验证模型异常、无效输入或重复请求不会让会话错误推进；仅能生成一次回复或串接多个 Prompt 不构成流程 Agent 的验收。

- [ ] 面试轮次先后不对，应先是面试官开启面试，而不是面试者先发送信息，另需要开始面试的接口和前端UI来启动。
- [ ] 设计并实现 `AssiantAgent`：随面试推进整理回答，为面试官追问提供参考。
- [ ] 明确总结的触发时机、输入输出、保留粒度和状态更新方式，再通过实际回答样例验证效果。
- [ ] 明确 `AssessAgent`、`EvaluateAgent` 的职责及接入时机；不将旧版评分能力视为已自动迁移。
- [ ] 补全简历上传、解析与上下文接入流程；区分文件路径和实际简历内容。

## 6. OpenAPI 接口契约与前端 SDK 自动化

状态：设计中。后端 FastAPI 代码及其运行时导出的 OpenAPI 规范为权威来源；尚未接入 SDK 生成、前端构建或 CI 校验。

- [ ] 确认应用启动后可访问 OpenAPI 规范，并记录实际的 `/openapi.json`、`/docs` 地址及其开发、测试环境的获取方式；如调整 `openapi_url` 或接口文档暴露策略，同步更新本项。
- [ ] 保持路由的 `tags`、请求模型、响应模型和操作标识稳定且语义清晰，使 OpenAPI 文档和生成后的前端方法可以按业务分组；不以手写接口说明替代后端实际注册的路由。
- [ ] 在前端以 Hey API 为候选生成器，先完成一次从 OpenAPI 规范到固定生成目录的 TypeScript SDK 生成验证；生成目录仅由生成器写入，业务页面不得手改其中的请求函数和类型。
- [ ] 确定开发期刷新策略：后端可访问时，前端开发/构建流程自动读取最新 OpenAPI 规范并重新生成 SDK；若开发环境不稳定，则先导出确定版本的规范文件作为生成输入，避免前端构建依赖偶然运行的本地服务。
- [ ] 在 CI 中依次执行“取得或导出 OpenAPI 规范 → 生成 SDK → 检查生成结果是否已同步 → 前端类型检查与构建”；后端接口改动不得在前端仍使用旧字段、旧路径或旧响应结构时通过。
- [ ] 约束 AI 与人工调用方式：前端仅从生成的 SDK 导入接口函数和类型，不重复手写 URL、HTTP 方法、请求体或响应类型；SDK 更新后的业务页改动必须通过类型检查、构建和必要的接口测试。

验收依据：任选一个已存在接口，变更其请求或响应模型并重新生成 SDK；确认生成结果发生预期变化、旧前端调用被类型检查识别，并在修正调用后通过前端构建。仅能访问 `/docs`、仅生成一次代码或仅由 AI 声称已对齐，均不构成自动化验收。

## 完成记录规则

任务完成时补充完成日期、验证方式和证据位置；未验证的实现仍保留验收项。版本发布后，将没有验证的结果与新遇到的问题统一整理成新的roadmap，旧roadmap以版本名+roadmap形式进行归档，不需要修改原内容，便于查看历史，放在archive文件夹中。
每个版本roadmap最多只能有七个验收清单，当出现多余写入时需要发出警告，必须严格遵守。
